# 游戏行业 AI智能客服+舆情监控自动化系统 - 产品需求规格书 (spec.md)

## Overview
- **Summary**: 搭建一套轻量化、可直接运行的游戏行业AI智能客服与舆情监控一体化系统，包含：网页端AI客服问答界面、多平台舆情数据抓取与情感分析、数据可视化Dashboard看板、简易AI工作流编排（评论采集→情感分析→打标签→负面预警）。
- **Purpose**: 解决游戏行业四大痛点：玩家咨询量大/AI客服意图识别不准、全网舆情分散无预警机制、无可视化数据看板支撑决策、产品经理缺乏AI Coding实战能力；产出可写进简历、可面试讲解、可直接演示的完整项目。
- **Target Users**: 游戏公司AI产品经理候选人（用于简历/面试）、游戏运营团队（客服与舆情监控场景）、游戏产品团队（数据决策场景）。

## Goals
### P0 核心刚需（AI Coding实战差异化能力）
1. 交付可直接打开运行的网页端AI智能客服界面，支持FAQ多轮对话、意图识别、陌生问题标记。
2. 交付舆情数据抓取脚本，适配TapTap/好游快爆/微博/贴吧公开评论数据的模拟抓取与去重分类归档。
3. 交付数据可视化Dashboard看板，覆盖客服4大指标+舆情4大指标。
4. 交付轻量化AI工作流编排逻辑：评论采集→情感AI分析→自动打标签→负面舆情预警。

### P1 业务架构能力（智能客服+舆情体系）
5. 完整客服业务链路：FAQ知识库管理→意图识别→多轮对话→问题分类→人工转接标记。
6. 完整客服指标可视化：CSAT满意度、NPS、转人工率、会话漏斗、咨询峰值统计。
7. 舆情情报体系：关键词监控、正负向情感分析、热点聚类、日报自动生成、突发负面预警。

### P2 产品思维落地
8. 玩家问题漏斗数据分析可视化。
9. 问题归类体系（系统性分类而非单点）。
10. 数据对比与迭代趋势展示。

## Non-Goals
- 不接入真实付费大模型API（使用本地模拟/规则引擎+Mock数据替代，保证零成本运行）。
- 不做真实平台爬虫绕过反爬机制（提供适配接口结构+Mock数据源，体现架构能力而非黑产风险）。
- 不做用户系统与权限管理（单用户/演示模式）。
- 不做移动端App（纯PC网页端）。
- 不做服务端持久化数据库（使用localStorage+本地JSON文件，轻量化可运行）。

## Background & Context
### 游戏行业普遍痛点（完全对标JD）
1. 玩家咨询量大、FAQ杂乱、AI客服意图识别不准、转人工率高、无系统化运维。
2. 全网玩家舆情分散在TapTap、好游快爆、微博、贴吧、Discord，无自动抓取、无情感分析、无预警机制。
3. 无自动化数据报表、无可视化看板，无法支撑产品迭代与运营决策。
4. 传统产品只会写文档，不会搭建AI工作流、不会做数据落地，缺乏AI Coding实战能力。

### 技术选型背景
- 前端：纯HTML+CSS+原生JavaScript（无需构建工具，双击可运行）。
- 图表：Chart.js CDN引入（无需npm安装）。
- 数据层：localStorage + mock/目录下的JSON文件。
- 脚本层：Python 3（舆情抓取+AI分析工作流，无需第三方重型库，仅需标准库+requests）。

## Functional Requirements

### P0 核心功能
- **FR-P0-1**: AI客服对话界面 — 玩家可在网页输入问题，系统返回FAQ匹配答案，支持多轮对话上下文展示。
- **FR-P0-2**: 意图识别与知识库命中 — 根据关键词/相似度将问题分类到知识库，未命中则标记为"待人工处理"。
- **FR-P0-3**: 陌生问题标记 — 知识库未命中的问题自动进入"待人工"列表，可在后台查看。
- **FR-P0-4**: 舆情数据抓取脚本 — Python脚本支持4个平台（TapTap/好游快爆/微博/贴吧）的评论结构化输出（JSON），含去重、分类、时间归档。
- **FR-P0-5**: 客服Dashboard可视化 — 展示响应时长、首次解决率、转人工率、满意度4大核心指标（含数值卡片+趋势图）。
- **FR-P0-6**: 舆情Dashboard可视化 — 展示好评率、差评率、热点事件聚类、每日舆情增量4大指标（含饼图+柱状图+热力图）。
- **FR-P0-7**: AI工作流编排 — 评论采集→情感分析→自动打标签→负面预警的端到端自动化流程，可一键运行并展示结果。

### P1 业务架构
- **FR-P1-1**: FAQ知识库管理 — 后台可增删改查知识库条目（问题、答案、分类标签）。
- **FR-P1-2**: 问题分类体系 — 至少5大类（账号问题/充值问题/游戏玩法/Bug反馈/建议投诉），可扩展。
- **FR-P1-3**: 人工转接标记 — 会话中可一键标记"转人工"并记录原因。
- **FR-P1-4**: 客服指标可视化扩展 — CSAT、NPS、会话漏斗、咨询峰值4类图表。
- **FR-P1-5**: 舆情关键词监控 — 用户自定义关键词，命中高亮。
- **FR-P1-6**: 情感分析 — 每条评论自动打正向/中性/负向标签及置信度。
- **FR-P1-7**: 热点聚类 — 按关键词将相似评论聚合成热点事件卡片。
- **FR-P1-8**: 舆情日报自动生成 — 一键生成结构化日报文本（平台分布、情感分布、热点Top3、负面预警），可复制导出。
- **FR-P1-9**: 负面预警提示 — 当负面评论超过阈值时，Dashboard红色预警横幅+声音提示开关。

### P2 产品思维
- **FR-P2-1**: 问题漏斗分析 — 展示咨询→AI解答→需追问→转人工的4级漏斗。
- **FR-P2-2**: 问题归类统计 — 饼图/条形图展示各问题分类占比。
- **FR-P2-3**: 数据对比与趋势 — 支持近7天vs上7天、今日vs昨日的指标对比，并以折线图展示迭代趋势。

## Non-Functional Requirements
- **NFR-1 可运行性**: 前端页面无需任何构建，双击 `index.html` 可直接在Chrome/Edge打开运行。
- **NFR-2 可演示性**: 自带Mock数据，首次打开即展示完整填充的看板，无空白页。
- **NFR-3 代码质量**: 代码注释完整（中文）、函数命名清晰、目录结构分明、可二次迭代。
- **NFR-4 性能**: 页面渲染首屏 < 2s（本地文件），单次AI意图识别响应 < 200ms。
- **NFR-5 UI/UX**: 简洁产品后台风格，主色使用游戏科技蓝紫渐变，卡片式布局，响应式适配1366×768及以上分辨率。
- **NFR-6 零依赖成本**: 所有CDN使用公共免费资源，Python脚本仅使用标准库或可 `pip install` 免费库。
- **NFR-7 业务真实性**: Mock数据贴合真实游戏场景（如《原神》《王者荣耀》类评论），拒绝无意义Lorem Ipsum。
- **NFR-8 可简历化**: 提供项目README，含项目简介、技术架构、核心能力、面试讲解要点。

## Constraints
- **Technical**:
  - 前端不得使用React/Vue/构建工具，纯原生HTML/CSS/JS以保证"双击可运行"。
  - 图表库使用Chart.js CDN版本。
  - 后端不运行Web服务（Django/Flask可选但非强制），舆情脚本以CLI方式运行，输出JSON供前端消费。
  - 持久化仅用localStorage + 本地JSON文件。
- **Business**:
  - 所有数据必须使用虚构的游戏名称和评论，不得引用真实在运营游戏的玩家隐私数据。
  - 项目运行不得产生任何费用（不得调用付费API）。
- **Dependencies**:
  - Python >= 3.8（运行舆情脚本可选）。
  - 现代浏览器：Chrome >= 90 / Edge >= 90 / Firefox >= 88。
  - Chart.js via CDN（需联网一次，之后浏览器缓存）。

## Assumptions
- 用户具备Chrome/Edge浏览器及基础操作能力。
- 面试/演示环境允许访问本地HTML文件和CDN资源。
- 若需运行Python脚本，用户可自行安装Python 3.8+。
- Mock数据量级可覆盖所有图表的可视化展示（单类数据点 >= 7个）。

## Acceptance Criteria

### AC-1: AI客服界面可运行
- **Type**: `rule`
- **Given**: 用户在文件管理器双击项目根目录 `index.html`
- **When**: 页面在浏览器中打开，切换到「智能客服」Tab
- **Then**: 出现对话消息区+输入框+发送按钮；输入"充值未到账怎么办"后3秒内显示AI回答
- **Pass Condition**: 界面渲染无报错，至少1条问题可收到非空回复
- **Evidence**: 浏览器打开截图+Console无JS错误

### AC-2: 意图识别与FAQ命中
- **Type**: `rule`
- **Given**: 知识库中存在条目{"问题":"如何修改密码","答案":"进入设置-账号安全-修改密码","分类":"账号问题"}
- **When**: 用户输入"怎么改密码呀"或"密码改不了"
- **Then**: 系统命中该FAQ并返回对应答案，消息气泡旁显示分类标签「账号问题」
- **Pass Condition**: 至少3组同义表述可命中同一FAQ
- **Evidence**: 对话历史截图+命中分类标签可见

### AC-3: 陌生问题标记待人工
- **Type**: `rule`
- **Given**: 用户输入知识库不存在的问题
- **When**: 发送该问题
- **Then**: AI回复"抱歉，该问题已为您标记至人工处理队列"，且在后台「待人工列表」中可查到该问题
- **Pass Condition**: 后台待人工列表中新增该条记录，含时间戳和问题内容
- **Evidence**: 对话回复截图+待人工列表截图

### AC-4: 舆情抓取脚本运行
- **Type**: `rule`
- **Given**: 已安装Python 3.8+
- **When**: 执行 `python scripts/crawl_sentiment.py` 或 `python scripts/crawl_sentiment.py --mock`
- **Then**: 在 `data/` 目录下生成 `comments_YYYYMMDD.json`，结构包含 {platform, content, author, time, sentiment, tags, hot_score} 字段；记录数 >= 50
- **Pass Condition**: JSON格式合法，字段完整，记录数达标
- **Evidence**: 脚本输出日志+生成的JSON文件 head 3条记录

### AC-5: 舆情抓取多平台适配
- **Type**: `rule`
- **Given**: 运行舆情脚本使用mock模式
- **When**: 检查生成JSON的platform字段值
- **Then**: 至少包含4种取值："TapTap" "好游快爆" "微博" "贴吧"，各平台记录占比均 >= 10%
- **Pass Condition**: 4个平台全覆盖，占比均衡
- **Evidence**: 按platform分组统计的命令输出

### AC-6: 客服4指标Dashboard可渲染
- **Type**: `rule`
- **Given**: 打开index.html切换到「数据看板」Tab
- **When**: 查看客服指标区域
- **Then**: 4张指标卡片（响应时长/首次解决率/转人工率/满意度）数值非空；至少2张图表（趋势折线图）成功渲染
- **Pass Condition**: 指标卡片有数值，Chart.js不报错
- **Evidence**: Dashboard截图+Console错误检查

### AC-7: 舆情4指标Dashboard可渲染
- **Type**: `rule`
- **Given**: 打开Dashboard
- **When**: 滚动到舆情指标区域
- **Then**: 好评率+差评率（饼图）、热点聚类（条形图/卡片）、每日舆情增量（柱状图）全部可见
- **Pass Condition**: 3类图表/组件均非空白
- **Evidence**: 舆情看板截图

### AC-8: AI工作流端到端可执行
- **Type**: `rule`
- **Given**: 在Dashboard页面点击「运行AI工作流」按钮
- **When**: 等待进度条走完
- **Then**: 依次展示4步状态：「已采集N条评论」「情感分析完成」「打标签完成」「产生K条负面预警」，并展示Top3负面预警卡片
- **Pass Condition**: 4步状态全部展示，负面预警卡片 >= 1张
- **Evidence**: 工作流执行完成后界面截图

### AC-9: FAQ知识库CRUD
- **Type**: `rule`
- **Given**: 切换到「知识库管理」Tab
- **When**: 点击"新增FAQ"填入问题/答案/分类并保存
- **Then**: 列表立即出现该条目；再点击编辑修改答案后保存可见；点击删除可移除
- **Pass Condition**: 增改查3步均可操作且结果持久化（刷新不丢）
- **Evidence**: 操作录屏或3步连续截图

### AC-10: 转人工标记链路
- **Type**: `rule`
- **Given**: 客服对话进行中
- **When**: 点击会话旁"转人工"按钮，选择原因"无法解决"
- **Then**: 对话标记为已转人工，该会话出现在「转人工统计」中，转人工率指标同步增加
- **Pass Condition**: 标记+统计+指标三端同步
- **Evidence**: 转人工操作截图+Dashboard转人工率变化

### AC-11: 客服扩展指标（CSAT/NPS/漏斗/峰值）
- **Type**: `rubric`
- **Dimension**: 指标完整性与可视化质量
- **Scale**: 1-5
- **Anchors**:
  - 1 = 仅P0 4指标，缺P1扩展指标
  - 3 = 4类指标存在但图表类型单一或数据量少
  - 5 = CSAT/NPS有分布条形、漏斗有阶梯图、峰值有24h热力柱，数据连贯覆盖7天
- **Pass Threshold**: >= 4
- **Evidence**: Dashboard客服扩展区域截图

### AC-12: 情感分析与标签
- **Type**: `rule`
- **Given**: 生成的舆情评论JSON
- **When**: 检查每条评论的sentiment字段和tags数组
- **Then**: sentiment∈{positive,neutral,negative}且含0-1置信度；tags含2-5个关键词（如"画质"/"卡顿"/"氪金"）
- **Pass Condition**: 抽查10条评论，sentiment字段合法率100%，tags非空率 >= 90%
- **Evidence**: 抽样检查记录

### AC-13: 热点聚类卡片
- **Type**: `rule`
- **Given**: Dashboard舆情区域
- **When**: 查看热点事件面板
- **Then**: 至少展示Top5热点事件卡片，每张卡片包含 关键词、评论数、情感倾向、代表评论摘要
- **Pass Condition**: 卡片 >= 5张，字段完整
- **Evidence**: 热点聚类面板截图

### AC-14: 舆情日报一键生成
- **Type**: `rule`
- **Given**: Dashboard存在舆情数据
- **When**: 点击"生成舆情日报"按钮
- **Then**: 弹出文本框，包含结构化段落：日期、总评论数、平台分布、情感分布、Top3热点、负面预警清单；有"复制到剪贴板"按钮可用
- **Pass Condition**: 文本长度 >= 200字，复制按钮功能正常
- **Evidence**: 日报弹窗截图+复制成功Toast提示

### AC-15: 负面预警横幅
- **Type**: `rule`
- **Given**: mock数据中负面评论占比 >= 30%
- **When**: 首次进入Dashboard或点击"运行工作流"完成
- **Then**: 顶部出现红色横幅："⚠️ 检测到高负面舆情风险：今日负面占比32%，主要集中在【服务器卡顿】"，可手动关闭
- **Pass Condition**: 横幅可见且文案与数据一致
- **Evidence**: 红色预警横幅截图

### AC-16: 玩家问题漏斗图
- **Type**: `rule`
- **Given**: Dashboard的「产品分析」子Tab
- **When**: 查看漏斗分析
- **Then**: 阶梯漏斗图4层依次为：总咨询量→AI匹配成功→需追问→转人工，层级数值递减且可见百分比
- **Pass Condition**: 漏斗图4层完整，数值合理
- **Evidence**: 漏斗图截图

### AC-17: 问题归类占比图
- **Type**: `rule`
- **Given**: 产品分析Tab
- **When**: 查看问题分类
- **Then**: 饼图/条形图展示至少5大分类（账号/充值/玩法/Bug/建议）占比
- **Pass Condition**: 5类完整且占比和为100%
- **Evidence**: 问题归类图截图

### AC-18: 趋势对比可视化
- **Type**: `rubric`
- **Dimension**: 数据对比维度丰富度与可读性
- **Scale**: 1-5
- **Anchors**:
  - 1 = 无趋势对比，只有今日静态数据
  - 3 = 存在折线趋势图但无同比环比对比
  - 5 = 同时提供近7日趋势线、本7日vs上7日对比卡片、今日vs昨日差值箭头（↑↓）和颜色（红涨绿跌或反之，可配置）
- **Pass Threshold**: >= 4
- **Evidence**: 趋势对比区域截图

### AC-19: 零构建可运行
- **Type**: `rule`
- **Given**: 全新Windows电脑无Node/Python环境
- **When**: 仅用Chrome打开index.html
- **Then**: 所有P0+P1界面正常渲染，Mock数据完整展示，不出现404资源请求或白屏
- **Pass Condition**: 首屏渲染 < 3s，Console无致命错误
- **Evidence**: 干净环境打开截图

### AC-20: 代码结构与注释
- **Type**: `rubric`
- **Dimension**: 代码可读性与可二次迭代性
- **Scale**: 1-5
- **Anchors**:
  - 1 = 单文件堆代码，无注释无目录
  - 3 = 分目录但关键函数缺注释或命名含糊
  - 5 = 目录结构清晰（public/{css,js}、scripts、data、mock、.trae/specs）；核心函数有中文注释说明入参/出参/用途；README说明运行方式、模块职责、简历讲解模板
- **Pass Threshold**: >= 4
- **Evidence**: 目录树截图+核心文件注释抽样

### AC-21: 业务真实性
- **Type**: `rubric`
- **Dimension**: Mock数据贴合真实游戏场景的程度
- **Scale**: 1-5
- **Anchors**:
  - 1 = Lorem Ipsum占位或与游戏完全无关
  - 3 = 泛泛使用"游戏出错了"等无行业特征文本
  - 5 = 客服FAQ覆盖账号/充值/Bug/防沉迷等真实分类；舆情评论包含"420抽未出UP""服务器炸了""新角色平衡"等行业黑话与典型痛点
- **Pass Threshold**: >= 4
- **Evidence**: FAQ和评论数据抽样截图

### AC-22: 简历README完整度
- **Type**: `rule`
